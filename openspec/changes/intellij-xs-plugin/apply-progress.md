## P0.5 — IDE behaviors

**Apply batch:** P0.5 IDE behaviors (extension of P0)  
**Branch:** `intellij-xs-plugin/p0-scaffold`  
**Target:** `master`  
**Completed at:** 2026-06-22

### What was completed

- Added a minimal JFlex lexer (`XsLexer.flex`) stub that recognizes braces, parentheses, brackets, string/char quotes, line/block comments, whitespace, identifiers, and a catch-all. The lexer is generated by the Grammar-Kit Gradle plugin into `src/main/gen/` (gitignored).
- Defined `XsTokenTypes` for the token types above, with `@JvmField` annotations so the generated Java lexer can reference them directly.
- Bridged the generated lexer to IntelliJ with `XsLexerAdapter`, which extends `com.intellij.lexer.FlexAdapter`.
- Added a minimal `XsParserDefinition` stub plus `XsFile`; the parser consumes tokens into a flat PSI tree so opening an `.xs` file does not crash while brace/quote behaviors still work.
- Implemented `XsBraceMatcher` providing structural pairs for `{ }`, `( )`, and `[ ]`.
- Implemented `XsQuoteHandler` for `"` and `'` quote handling.
- Implemented `XsCommenter` with `//` line comments and `/* */` block comments.
- Added `XsSurroundingPairsProvider` as a typed source-of-truth for the five character pairs that wrap selections.
- Registered `lang.parserDefinition`, `lang.braceMatcher`, `lang.quoteHandler`, and `lang.commenter` extension points in `plugin.xml`.

### Deviations from the spec

- `com.intellij.lang.surroundingPair.SurroundingPairsProvider` does not exist in IntelliJ Platform 2024.2 (the plugin's target baseline). Surrounding-pair behavior is instead provided by the platform's brace matcher / quote handler integration, while `XsSurroundingPairsProvider` keeps the pair list testable and ready for the API when it becomes available.
- `XsParserDefinition.createParser` returns a minimal flat-tree parser instead of throwing, because opening an `.xs` file in the IDE triggers PSI construction and a throwing stub would break basic editing.
